## 읽는 법

**사람 → 팀장** 은 짧고 거칩니다. 화면을 보다가 떠오르는 대로 칩니다. 팀장의 일은 그 말을 범위와 완료 기준이 있는
작업으로 바꾸는 것입니다. 예를 들어 "찰랑 찰랑 차올라야하거든 기울이면 기운채로도 할수있나" 는 물 표면 물리, 기울기 센서,
쏟기 규칙, 시뮬레이션 검증으로 나뉘어 여러 작업자에게 갔습니다.

**팀장 → 작업자** 는 한 번에 다 적습니다. 작업자는 앞뒤 대화를 모르기 때문입니다. [env-worker.md](env-worker.md) 의
첫 지시를 보면 이런 순서입니다.

1. 누구이고 왜 보내는지, 저장소와 먼저 읽을 문서
2. 건드리지 말 곳(팀장이 쓰는 폴더와 파일)
3. 작업 트리를 만드는 명령 그대로(브랜치 이름과 기준 커밋 포함)
4. 할 일을 번호로, 숫자는 숫자로(“+0.04, 0.3초 유예, 초당 0.25 감소”)
5. 확인 방법(테스트를 먼저, 어떤 명령이 통과해야 하는지)
6. 어디까지 하는지(커밋까지, push 와 PR 은 팀장)
7. 보고 형식(브랜치, 요약, 명세와 다르게 판단한 점)

**작업자 → 팀장** 보고는 돌려 본 결과를 숫자로 적습니다(통과 개수, 걸린 시간). 실패, 건너뛴 것, 판단한 점을 숨기지 않습니다.
[review.md](review.md) 의 Codex 보고는 심각도 순 목록에 재현 방법까지 붙어 있어 리뷰 보고의 좋은 예입니다.

**사람이 결정을 바꾸는 장면** 도 그대로 남겼습니다. 지도의 "동네 행복 비율" 은 원칙과 부딪힌다고 감췄다가 사람이
"보기만 하는 것" 이라며 켰고, 조사 쪽은 연구를 근거로 다시 끄자고 했습니다. 결정은 사람이 하고, 팀장은 어느 쪽이든
상수 한 줄로 바뀌게 만들어 둡니다.

## 다듬은 것

원문을 그대로 두되 공개 저장소에 맞게 이것만 바꿨습니다.

- 실제 도메인, 서버 이름, 홈 경로, 저장소 주인 이름, 다른 프로젝트 이름을 `example.com`, `server`, `~/`, `<owner>` 같은 값으로
- 40자 커밋 해시를 앞 7자로
- 거친 말 몇 개를 `(…)` 로
- 한 사람이 몇 초 사이에 끊어 친 말을 한 덩어리로

시간은 UTC 입니다. 이 폴더는 원문 기록이라 AI 말투 검사(`slop_scan.py`)에서 뺐습니다. 개인정보 검사는 그대로 받습니다.
