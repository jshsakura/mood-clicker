# 기분 클리커 계획 (가칭)

작성 2026-11-18. 이 문서는 초기 설계 계획이며, 현재 1단계 파일럿 기능(도메인, JSON 저장, 화면, 진동·소리, 설정, 알림·위젯)은 구현되었습니다. 현행 규격은 [기능 명세](SPEC.md) 를 따릅니다.

## 한 줄 정의

오늘의 기분을 고르고 연타한 횟수로 그 기분이 얼마나 컸는지 남긴다. 날짜별로 행복과 슬픔을 나눠 보여 주고,
나중에는 다른 사람들의 그날 기분을 지도로 함께 본다.

## 출시 대상과 기술

- 안드로이드, 아이폰이 본선이고 맥은 파일럿이다.
- Flutter 하나로 세 곳을 낸다.
- 안드로이드 빌드와 테스트는 이 서버의 Flutter 도커(`ghcr.io/cirruslabs/flutter:stable`, 3.44)에서 한다.
- 아이폰과 맥 빌드는 맥이 필요하다. 맥이 없으면 GitHub Actions 의 macOS 러너로 빌드한다.
- 진동 손맛은 에뮬레이터로 확인할 수 없으니 실기기에서 본다.

## 핵심 규칙

1. 기분을 하나 고른다. 기분마다 행복 쪽인지 슬픔 쪽인지가 정해져 있다.
2. 연타한다. 한 번 누를 때마다 진동과 애니메이션이 반응한다.
3. 연타 수가 그 기분의 강도가 된다.
4. 하루에 여러 번 남길 수 있다. 그날의 행복 합계와 슬픔 합계를 따로 쌓는다.

정해야 할 것:

- 기분 목록. 몇 개로 할지, 중립 기분을 둘지.
- 연타를 어떻게 끊을지. 제안은 "10초 동안 누른 만큼" 이다. 시간 제한이 없으면 오래 누른 사람이 이기는 게임이 된다.
- 손가락 여러 개로 동시에 누르는 것을 셀지.

## 데이터

```
Mood      { id, 이름, 쪽(행복|슬픔) }
Session   { 날짜, 기분, 연타 수, 시각 }
DaySummary{ 날짜, 행복 합계, 슬픔 합계 }   // Session 에서 계산한다. 따로 저장하지 않는다.
```

초기 계획에서는 SQLite 를 적었으나, 현재 파일럿은 기기 안 JSON 파일(`DayRecord` v2)로 저장한다. 지도 단계(계획)에서 서버 동기화를 붙인다.

## 화면

- 오늘: 기분 고르기, 연타 버튼, 방금 남긴 강도.
- 기록: 날짜별 행복과 슬픔 막대, 달력 보기.
- 지도: 3단계에서 추가한다.

## 진동과 애니메이션은 Flutter로 되는가

결론은 된다. 진동은 플러그인으로, 애니메이션은 Flutter가 오히려 강한 쪽이다.

### 진동

| 필요한 것 | 방법 |
|---|---|
| 탭마다 짧은 톡 | Flutter 기본 `HapticFeedback.lightImpact()` 등. 플러그인도 필요 없다 |
| 세기와 패턴 조절 | `vibration` 같은 플러그인. 안드로이드는 세기 조절, 아이폰은 Core Haptics 패턴 |
| 플러그인으로 부족할 때 | 플랫폼 채널로 Swift, Kotlin 코드를 직접 부른다. 수십 줄 규모다 |
| 맥 | 진동이 없다. 포스터치 트랙패드 햅틱만 채널로 부를 수 있다 |

주의할 점: 초당 10회 넘게 연타하면 기기에 따라 진동이 뭉개진다. 빠르게 누를 땐 진동 간격을 조절하는
처리가 필요하고, 이건 실기기로 맞춰야 한다.

### 애니메이션

Flutter는 화면을 직접 그리기 때문에(Impeller 엔진) 플랫폼 기본 화면을 쓰는 앱보다 자유롭다.

- 눌림, 튕김, 숫자 올라가기: 기본 애니메이션과 스프링 물리로 된다.
- 연타할 때 튀는 입자, 화면 흔들림: `CustomPainter` 로 직접 그린다.
- 호일 같은 금속 광택, 구겨짐: 프래그먼트 셰이더(GLSL)로 그린다. 폰 기울기 센서와 엮어 반사광을 움직일 수 있다.
- 디자이너가 만든 애니메이션: Rive, Lottie 를 그대로 재생한다.

Flutter로 안 되는 것은 홈 화면 위젯이다. 위젯 화면 자체는 아이폰은 SwiftUI, 안드로이드는 Kotlin으로
따로 만들고, 데이터만 Flutter와 나눈다(초기 계획상 3단계 이후였으나, 현재 파일럿에 위젯 기본 구현이 들어갔고 실기기 확인이 남아 있다).

## 단계

### 0단계: 기술 확인 (먼저 한다)

Flutter로 정말 손맛이 나는지 작게 만들어 확인하고 넘어간다.

- 버튼 하나, 연타 시 진동, 입자 효과, 금속 광택 셰이더 하나.
- 안드로이드 실기기와 아이폰 실기기에서 초당 10회 연타로 끊김과 진동을 본다.
- 통과 기준: 120Hz 기기에서 끊김 없이, 진동이 탭과 어긋나지 않는다.
- 안 되면 진동만 플랫폼 채널로 바꾼다. 그래도 안 되면 그때 기술 선택을 다시 본다.

### 1단계: 내 기록 파일럿

- 기분 고르기, 연타, 날짜별 행복과 슬픔 기록, 기록 화면.
- 기기 안 저장. 계정 없음, 서버 없음.
- 기록 계산은 테스트로 고정한다.

### 2단계: 디자인

- 쿠킹호일 디자인 요소를 입힌다. 무엇을 가져올지는 보류 중이다.

### 3단계: 함께 보는 지도

- 서버, 익명 계정, 기분 업로드.
- 위치는 정확한 좌표를 올리지 않는다. 동네 크기 격자로 뭉개서 올리고, 지도에는 격자별 합계만 그린다.
- 한 격자에 사람이 일정 수 미만이면 표시하지 않는다. 한 명뿐인 동네에서 누구 기분인지 드러나기 때문이다.
- 지도는 MapLibre + OpenFreeMap 으로 정했다(지금은 예시 자료로 그린다).

#### 서버는 Supabase 로 붙인다 (계획, 2026-11-19 갱신)

고른 이유: 가입 없는 익명 로그인, Postgres 의 행 단위 보안(RLS)으로 "남의 행은 못 본다" 를 DB 가 지킨다, 오픈소스라 나중에 직접 호스팅으로 옮길 수 있다. 처리방침(`docs/PRIVACY.md`)이 이미 이 구조를 전제로 쓰여 있다.

보내는 것과 안 보내는 것은 처리방침 그대로다. 설정에서 "지도에 내 기분 보태기" 를 켠 사람만, 기분 종류·횟수·날짜·H3 해상도 7 격자 번호를 보낸다. 좌표, 메모, 오늘의 한마디, 달력 기록은 보내지 않는다. 개인 기록 동기화(백업)는 이 단계에 넣지 않는다.

##### 구조

| 부분 | 내용 |
|---|---|
| 인증 | 익명 로그인. 앱 첫 참여 때 한 번 만들고 기기에 둔다. 이메일, 소셜 로그인 없음 |
| 테이블 | `mood_drops(user_id, day, cell, mood, taps, updated_at)`. 기본 키 `(user_id, day, mood)`. 한 사람이 하루 기분당 한 줄이고 다시 보내면 덮어쓴다(upsert) |
| 쓰기 규칙(RLS) | 앱은 테이블에 직접 닿지 않는다. 쓰기는 함수 `put_mood_drop(day, cell, mood, taps)` 하나로, 부른 사람의 `auth.uid()` 줄만 upsert 한다. RLS 는 켜고 정책은 두지 않으며 `anon`, `authenticated` 의 테이블 권한도 뺀다. upsert 는 select 정책을 요구해서, 직접 쓰기를 열면 자기 줄 읽기까지 열어야 하기 때문이다 |
| 읽기 | 집계 함수 `mood_map(from, to, cells[])` 하나만 연다. 기간은 하루에서 이레, 격자는 한 번에 2000개까지다. 격자별 기분 합계를 돌려주되, 그날 참여한 사람이 5명 미만인 격자는 빼고 돌려준다. `security definer` 로 원본을 읽고, 함수 밖으로는 합계만 나간다 |
| 서버 검사 | `check` 제약과 트리거로 거른다. 앱을 믿지 않는다. 기분은 다섯 이름 중 하나, 횟수는 0 이상 상한 이하, 날짜는 서버 날짜 앞뒤 하루, 격자는 아래 H3 검사 |
| H3 검사 | Supabase 확장 목록에서 `h3` 를 확인하지 못했다. 확장 없이 격자 번호(bigint)의 비트로 검사한다. 모드 비트가 셀(1)이고 해상도 비트가 7 인지 본다. 확장이 있으면 그것으로 바꾼다 |
| 남용 막기 | 익명 가입은 Supabase 가 IP 당 시간에 30번으로 막는다. 익명 계정이 DB 를 부풀릴 수 있어서 Supabase 는 CAPTCHA(hCaptcha, Turnstile)를 권한다. 처음에는 쓰기 횟수 제한(한 계정 하루 쓰기 상한)을 DB 트리거로 두고, CAPTCHA 는 출시 전에 정한다 |
| 보관 | 정한 기간(30일 또는 90일)이 지난 줄은 `pg_cron` 예약 작업으로 매일 지운다. 줄이 없는 익명 계정도 같이 지운다 |
| 내 자료 지우기 | 함수 `delete_my_data()` 하나로 그 사람 줄과 익명 계정을 함께 지운다. 설정의 "지도 참여 끄기" 가 부른다 |
| 앱 쪽 | `supabase_flutter`. 지도 자료를 `MoodMapRepository` 인터페이스 뒤로 옮기고, 지금 예시 자료와 Supabase 구현을 갈아 끼운다 |
| 보내는 때 | 연타가 끝나고 몇 초 뒤 한 번 upsert 한다. 네트워크가 없으면 그날 줄 하나만 기기에 들고 있다가 다음에 보낸다. 지도 읽기는 격자 묶음 단위로 몇 분 캐시한다 |
| 주소와 키 | 프로젝트 주소와 anon 키는 저장소에 적지 않는다. 빌드 때 `--dart-define` 으로 넣는다(개인정보 검사가 도메인을 막는다). anon 키는 앱에 들어가는 공개 키라 RLS 가 유일한 방어선이다. `service_role` 키는 앱, 저장소, CI 로그 어디에도 두지 않는다 |
| 환경 | 로컬(도커의 Supabase CLI), 시험 프로젝트, 운영 프로젝트 셋. 스키마는 `supabase/migrations/` 하나에서 만들고 같은 마이그레이션을 차례로 올린다. 대시보드에서 손으로 고치지 않는다 |

##### 사람이 해야 하는 일

에이전트가 대신할 수 없다. 계정, 결제, 법적 책임이 걸려 있다.

1. Supabase 조직과 시험 프로젝트를 만든다. 지역은 서울이 있으면 서울을 고른다(만들 때 목록에서 확인). 국외 지역이면 처리방침에 국외 이전을 적어야 한다.
2. 인증 설정에서 익명 로그인을 켠다.
3. 프로젝트 주소와 anon 키를 팀 채널로 받는다. `service_role` 키와 DB 비밀번호는 팀장만 보관한다.
4. 요금제를 정한다. 무료 요금제는 7일 동안 활동이 적으면 프로젝트를 멈춘다. 시험 단계는 무료로 두고, 출시 전에 유료(Pro)로 올릴지 정한다.
5. 처리방침의 빈칸(수탁자 Supabase, 보관 기간, 문의 이메일, 국외 이전 여부)을 채우고, 스토어 개인정보 양식(플레이 데이터 보안, 앱 스토어 개인정보 라벨)에 "익명 식별자, 대략적 위치(격자), 앱 활동" 을 적는다.

##### 순서

단계마다 테스트가 통과한 상태로 끝낸다. 1~3 은 Supabase 프로젝트 없이 할 수 있다.

1. **스키마와 RLS 테스트(로컬).** (2026-11-25 완료: `supabase/migrations/20261125000000_mood_map.sql`, `supabase/tests/mood_map_test.sql` 27개. 로컬 API 로 익명 로그인, 보내기, 원본 읽기 거절, 지도 읽기, 지우기까지 확인했다. 정할 숫자는 `map_min_people()`, `map_keep_days()`, `map_max_writes()`, `map_max_taps()` 함수 하나씩에 두었다.) `supabase/migrations/` 에 테이블, 제약, RLS, 집계 함수, 지우기 함수, 보관 작업을 둔다. pgTAP 테스트(`supabase test db`)를 먼저 쓴다. 남의 줄 쓰기 거절, 원본 읽기 거절, 5명 미만 격자 숨김, 잘못된 격자·기분·날짜·횟수 거절, 지운 계정의 줄 없음, 보관 기간 지난 줄 삭제.
2. **CI.** `ci.yml` 에 Supabase CLI 로 로컬 DB 를 띄워 1 의 테스트를 돌리는 작업을 따로 넣는다. 7GB Flutter 이미지와 섞지 않는다.
3. **앱의 경계.** `MoodMapRepository` 를 두고 예시 자료 구현으로 지금 지도 화면이 그대로인지 골든과 위젯 테스트로 확인한다.
4. **앱의 Supabase 구현.** 설정의 참여 켜기·끄기(켤 때 무엇을 보내는지 한 화면으로 설명), 보내는 때, 오프라인 보관, 내 자료 지우기를 붙인다. 가짜 저장소로 위젯 테스트를 쓴다. 주소와 키가 없으면 참여 메뉴가 숨는다.
5. **시험 프로젝트.** 사람이 만든 시험 프로젝트에 마이그레이션을 올리고 테스트 빌드에서만 켠다. 지도가 5명 기준을 넘기 전까지는 빈 지도가 정상이다.
6. **출시 준비.** 처리방침과 스토어 양식, CAPTCHA 여부, 요금제, 운영 프로젝트를 정하고 같은 마이그레이션을 운영에 올린다.

##### 정해야 할 것

- 보관 기간: 30일 또는 90일
- 지역: 서울이 있는지 만들 때 확인. 없으면 도쿄나 싱가포르와 국외 이전 고지
- 5명 기준 유지 여부
- 하루 쓰기 상한(남용 막기)과 CAPTCHA 도입 시점
- 요금제: 시험은 무료, 출시 때 Pro 여부

### 4단계: 출시

- 플레이 스토어, 앱 스토어. 위치 권한 설명 문구와 개인정보 처리방침이 필요하다.
- 맥은 파일럿으로 같은 코드에서 낸다.
