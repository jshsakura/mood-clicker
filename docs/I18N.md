# 다국어 안내 (i18n)

작성 2026-11-18. 디자이너와 번역자가 문구를 고치거나 언어를 더할 때 보는 문서입니다.

## 어디에 무엇이 있나

| 역할 | 위치 |
|---|---|
| 화면 문구 원본 | `lib/l10n/app_ko.arb` (템플릿), `app_en.arb`, `app_ja.arb` |
| 생성 파일 | `lib/l10n/app_localizations*.g.dart` (손대지 않습니다) |
| 날짜와 요일 | `lib/l10n/date_labels.dart` (intl DateFormat 이 로케일에 맞게 만듭니다) |
| 언어 선택 값 | `lib/l10n/locale_choice.dart`, `locale_choice_prefs.dart` |
| 지원 밖 언어 처리 | `lib/l10n/locale_resolution.dart` (영어로 대체) |
| 응원 문구 | `assets/cheers/<언어>.json` |
| 도장 그림 | `assets/stamps/<언어>/well_done.svg` |
| 앱 이름 | 안드로이드 `android/app/src/main/res/values-*/strings.xml`, iOS `ios/Runner/<언어>.lproj/InfoPlist.strings` |

## 화면 문구 고치는 법

1. `app_ko.arb` 에서 문구를 고칩니다. 키 규칙은 `화면_요소` 입니다(예: `moodSelect_moodHappy`).
   `@키` 의 description 에 그 문구가 어디에 쓰이는지 적어 둡니다.
2. 숫자를 세는 문구는 ICU 복수형을 씁니다. 이미 있는 `tap_todayCount` 를 본뜨면 됩니다.
   ```json
   "tap_todayCount": "{count, plural, other {오늘 {count}}}"
   ```
3. `app_en.arb`, `app_ja.arb` 의 같은 키를 채웁니다. 키와 `{자리표시자}` 는 템플릿과 같아야 합니다.
   문구 안에 날짜가 들어가야 하면 `review_mostTappedDay` 처럼 DateTime 자리표시자에 `format` 을 붙입니다.
4. `tool/fl gen-l10n` 으로 생성 파일을 다시 만들고 함께 커밋합니다.
5. `tool/test.sh` 와 `tool/fl analyze` 가 통과하는지 봅니다.

날짜, 달, 요일 이름은 ARB 에 넣지 않습니다. `date_labels.dart` 의 `monthTitle`, `weekdayLabels`, `dayTitle` 이
로케일에 맞는 형식으로 만들어 주므로 화면 코드는 이 함수만 부릅니다.

## 언어 더하는 법

1. `app_en.arb` 를 복사해 `app_<언어>.arb` 를 만들고 모든 키를 번역합니다.
2. `tool/fl gen-l10n` 을 돌립니다. 지원 언어는 ARB 파일 목록에서 정해집니다.
3. 안드로이드: `values-<언어>/strings.xml` 을 만들고 `res/xml/locales_config.xml` 에 locale 을 추가합니다.
4. iOS: `ios/Runner/<언어>.lproj/InfoPlist.strings` 을 만들고 `Info.plist` 의 `CFBundleLocalizations` 에 추가한 뒤
   Xcode 프로젝트에 등록합니다(개발자에게 부탁합니다).
5. 설정의 언어 선택지(`LocaleChoice` 와 ARB `settings_language*` 키)는 개발자가 추가합니다.
6. 응원 문구와 도장도 그 언어판이 있으면 좋습니다. 없으면 한국어판으로 대체되므로 비워 둬도 앱은 깨지지 않습니다.

## 응원 문구 넣는 법

`assets/cheers/<언어>.json` 에 기분별로 단계마다 문구를 둡니다.

```json
{
  "version": 1,
  "moods": {
    "happy": {
      "low": ["시작이 반이에요", "오늘도 좋아요"],
      "high": ["기분 좋네요"],
      "full": ["행복이 넘쳐요"]
    }
  }
}
```

- 기분 id 는 다섯 개로 정해져 있습니다: `happy`, `excited`, `angry`, `sad`, `anxious`.
- 단계는 `low`, `high`, `full` 세 개이고, 빈 묶음은 두지 않습니다.
- 언어마다 문구 개수가 달라도 됩니다. ARB 처럼 키를 맞출 필요가 없습니다.
- 문구 길이는 `tool/cheers_check.py` 가 언어별로 정합니다(한국어와 일본어 2~14자, 영어 2~20자). 화면 쪽은 문구가 길면 글자 크기를 줄여 화면 너비의 60% 안에 맞추므로 `l10n_check` 는 길이를 따지지 않습니다. 지킴이의 경고는 기본으로 종류별 개수 한 줄만 보여 주고, `python3 tool/l10n_check.py --verbose` 가 전부 보여 줍니다. 오류는 언제나 전부 보여 줍니다.
- 새 언어 파일을 넣었으면 `pubspec.yaml` 의 assets 목록에도 추가합니다.

## 도장 문구

도장("참 잘했어요" 류)은 글꼴로 그리지 않고 디자이너가 만든 SVG 로 보여 줍니다.
`assets/stamps/<언어>/well_done.svg` 자리에 넣고, 없는 언어는 한국어판으로 대체합니다.
그림이 들어오면 `pubspec.yaml` 의 assets 목록에 폴더를 추가합니다.

## 지킴이

`tool/l10n_check.py` 가 커밋과 CI 에서 다음을 검사합니다.

- 모든 ARB 가 템플릿과 키, 자리표시자가 같은지.
- 응원 문구 JSON 이 약속한 형식(버전, 기분 다섯 개, 단계 세 개, 빈 묶음 없음)인지.
- 영어와 일본어 파일(ARB 값, 응원 문구)에 한글이 섞이지 않았는지. 정말 필요한 예외(예: 언어 이름 `settings_languageKo`)는 `tool/l10n_allow.json` 에 키와 이유를 적습니다. 응원 문구는 문구 자체가 키입니다. 더는 필요 없어진 항목이나 이유가 빈 항목은 오류입니다.

CI 는 `flutter gen-l10n` 을 다시 돌려 생성 파일이 ARB 와 같은지도 확인합니다. 화면 문구를 코드에 직접 적으면
`slop_scan.py` 의 한글 검사가 막습니다. 문구는 언제나 ARB 키로 부릅니다.

## 글꼴과 일본어

앱에 넣은 Pretendard 는 한글 2,350자와 라틴, 문장부호만 남긴 서브셋입니다(`tool/subset_fonts.py`).
일본어 가나와 한자는 빠져 있습니다(2026-11-18 fontTools cmap 확인).

- 기기에서는 빠진 글자가 시스템 글꼴로 대체되어 보입니다. 다만 Pretendard 와 시스템 글꼴의 모양과 줄 높이가
  달라 한 줄 안에 섞이면 티가 날 수 있습니다. 실기기에서 일본어 화면을 눈으로 확인합니다.
- 골든 테스트에서는 시스템 글꼴이 없어 일본어가 네모(결자)로 그려집니다. 글자 모양까지 보려면 테스트 안에서
  Noto Sans JP 를 FontLoader 로 실어야 합니다.

대책 제안(결정 필요):

1. 일본어 로케일에서는 Pretendard 대신 시스템 글꼴을 쓰거나, Noto Sans JP 서브셋을 앱에 넣고 로케일별로 고릅니다.
2. 골든 테스트에서 일본어를 그릴 일이 있으면 그 테스트에서만 Noto Sans JP 를 실습니다.
