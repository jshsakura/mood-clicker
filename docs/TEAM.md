# 작업판

다섯 세션이 이 판을 보고 일한다. 이 파일은 팀장(12.1)만 고친다. 다른 세션은 읽기만 하고, 결과는 `itl send 12.1` 로 보고한다.

## 지금 목표

**사장님 폰에서 두드려 볼 수 있는 POC.** 기분 고르기 → 두드리기(채움, 진동, 소리) → 달력까지 한 바퀴 돈다.
지도와 서버는 이번 목표가 아니다. 디자인은 토큰과 부품 자리까지만 만들고 꾸미지 않는다. 네이티브 앱처럼 느껴져야 하고 웹앱처럼 보이면 안 된다.

## 역할

| 팬 | 세션 | 역할 |
|---|---|---|
| 12.1 | Claude Opus | 팀장, 주력 개발. 핵심 로직, 화면 연결, 검수, 브랜치 합치기 |
| 12.2 | Claude Sonnet | 잡무. 플랫폼 셸 설정, 아이콘, 스플래시 |
| 12.3 | Antigravity | 조사. 출처와 확인 날짜를 단다 |
| 12.4 | Codex | 적대적 리뷰. 코드를 고치지 않고 문제만 보고한다 |
| 12.5 | Claude Sonnet | 개발과 문서. 진동·소리 계층, 문서 정리 |

## 규칙

1. 일을 받으면 `AGENTS.md`, `docs/SPEC.md` 를 먼저 읽는다.
2. 작업은 자기 작업 트리에서만 한다. 원래 폴더(`~/workspace/mood-clicker`)는 팀장 자리라 건드리지 않는다.
   `git -C ~/workspace/mood-clicker worktree add ~/workspace/mood-clicker-<이름> -b <브랜치> <기준 커밋>`
3. 맡은 경로 밖의 파일을 고치지 않는다. 꼭 필요하면 고치기 전에 팀장에게 묻는다.
4. 커밋까지만 한다. push, PR, 합치기는 팀장이 한다. 훅을 건너뛰지 않는다.
5. 끝나면 `itl send 12.1` 로 브랜치, 커밋, 세 줄 요약, 명세와 다르게 판단한 점을 보낸다.
6. 막히면 30분 넘게 붙들지 말고 막힌 이유를 보고한다.
